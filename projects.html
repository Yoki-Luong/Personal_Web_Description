Patient Referral Management System

MIS 3371 capstone, University of Houston

August 2026 to present
Team of 5, in progress

The problem

Clinics send referrals by phone, fax, paper, and email. Coordinators re-type the details, chase missing information, and route referrals by hand, so referrals get lost, duplicates happen, and providers can't see the status.

The system

Our team built a transaction processing system for one transaction: a provider submits a patient referral for a service. The system checks the required fields, blocks duplicate active referrals, assigns a referral ID, and routes the referral to the right department. That department accepts it, rejects it with a reason, or asks for more information, and every status change is recorded with a timestamp.

What I do

  • I serve as the team's QA and Testing Lead.
  • Our documentation includes a 15-field data dictionary covering data types, validation rules, business rules, and system-generated fields.
  • I use GitHub for version control, reviewing code changes and coordinating with my team throughout development.

Where it stands

The front end (HTML, CSS, and JavaScript) is complete, with validation and business rules such as duplicate blocking and a review window that depends on urgency. A local Node.js backend passes 21 tests. All demo data is fictional.

Tools: HTML, CSS, JavaScript, Node.js, GitHub, VS Code.
